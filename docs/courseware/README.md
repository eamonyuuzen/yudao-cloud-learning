## 1. 这个目录解决什么问题

以前的 `roadmap/` 回答“以后学什么”，`stages/` 回答“当前阶段为什么这样学”。本目录进一步回答：

```text
今天坐下后先打开什么
→ 先建立哪张人类逻辑图
→ 只读哪几个真实文件
→ 用户亲手决定和编写什么
→ 卡住时按哪一级提示
→ 完整参考代码在哪里
→ 用什么命令和现象验收
→ 什么时候停止下钻并进入下一轮
```

它是备课包，不是新的知识库。经运行证据验证且可跨项目复用的结论，阶段收尾时再整理到 Engineering-Knowledge。

## 3. 解锁规则

代码已经提前备好，不代表学习时一开始就把答案全部展示出来。

默认解锁顺序：

```text
第一层：目标、角色图、事件伪代码
→ 第二层：真实文件地图和输入输出
→ 第三层：注释骨架或方法签名
→ 第四层：局部代码提示
→ 第五层：完整参考实现
```

只有出现以下情况之一，才提前打开完整参考代码：

- 用户已完成自己的版本，需要审查；
- 同一个边界连续两次受阻；
- 当前代码属于机械施工，不承载本轮业务判断；
- 用户明确要求 AI 接管实现；
- 当天目标是运行、排错或比较，而不是手写。

## 4. 用户与 AI 的默认分工

用户优先亲自完成：

```text
能力契约
业务状态和不变量
权限和数据范围
正常/失败分支
幂等键、锁粒度、事务边界
验收证据和“什么算失败”
```

AI 可以提前完成：

```text
文件骨架
重复注解和普通 DTO
环境变量模板
机械 HTTP 客户端
测试脚手架
构建命令
格式、导包和编译收尾
```

AI 接管代码后必须回报：

```text
改了什么
哪一段仍需要用户审查
可能错在哪里
用什么证据验证
```

## 5. 每轮固定节奏

### 90 分钟核心模式

```text
5 分钟：从总图定位今天只解决哪个根问题
15 分钟：人类逻辑和一个可手算/可模拟小例子
20 分钟：只读一个参考链，第一入口 + 最多四个可选文件
30 分钟：用户编写或审查一处代表性代码
15 分钟：运行一个正常或失败实验
5 分钟：向上抽象、记录证据和停车场
```

### 有余力扩展模式

```text
再加 30～90 分钟：
第二个失败/并发实验
→ 补完整实现或横向源码对照
→ 只处理当天已经暴露的问题
```

不是每轮都必须写新代码。源码阅读、故障实验和架构复述只要形成有效证据，也算完整一轮。

## 6. 深度控制

| 内容 | 默认深度 | 到什么程度停止 |
|---|---|---|
| 业务状态、权限、事务、幂等 | 实现层 | 能修改、预测失败并用证据验证 |
| Spring 注解和框架钩子 | 机制层 | 能跑通一次“启动连接 + 运行时事件” |
| 第三方 SDK 普通语法 | 黑盒或机制层 | 知道输入输出、错误和替换边界 |
| Agent 运行时源码 | 代表性实现层 | 能把显式循环映射到一条真实路径，不通读产品 |
| MySQL 锁与隔离 | 机制 + 代表 SQL | 能解释两个并发事务的时间线 |
| Redis/MQ 底层存储 | 黑盒层 | 能解释可靠性边界，不进入源码 |
| JVM、Netty、Docker 内核 | 当前停车 | 不阻塞当前实验即可 |

停止下钻条件：

```text
已经能回答谁先接住调用
→ 根据什么匹配下一处理者
→ 谁拥有状态和业务判断
→ 一个正常与一个失败分支怎样结束
→ 再下钻不会改变设计或验证方法
```
