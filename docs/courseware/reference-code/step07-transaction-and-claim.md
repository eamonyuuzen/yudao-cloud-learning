## 5. Service

接口：

```java
void claimInternshipTask(Long taskId, Long userId);
```

实现：

```java
@Override
@Transactional(rollbackFor = Exception.class)
public void claimInternshipTask(Long taskId, Long userId) {
    int updateCount = internshipTaskMapper.claim(
            taskId,
            userId,
            InternshipTaskStatusEnum.TODO.getStatus(),
            InternshipTaskStatusEnum.IN_PROGRESS.getStatus());

    if (updateCount == 0) {
        InternshipTaskDO task = internshipTaskMapper.selectById(taskId);
        if (task == null) {
            throw exception(INTERNSHIP_TASK_NOT_EXISTS);
        }
        if (task.getAssigneeUserId() != null) {
            throw exception(INTERNSHIP_TASK_ALREADY_CLAIMED);
        }
        throw exception(INTERNSHIP_TASK_NOT_CLAIMABLE, task.getStatus());
    }

    InternshipTaskClaimDO claim = new InternshipTaskClaimDO();
    claim.setTaskId(taskId);
    claim.setUserId(userId);
    claim.setClaimTime(LocalDateTime.now());
    internshipTaskClaimMapper.insert(claim);
}
```

事务保护：

```text
任务原子更新
认领记录插入
```

如果插入因唯一约束或人工故障失败，前面的任务更新一起回滚。

### 封住旧的状态入口

从这一阶段开始，`TODO → IN_PROGRESS` 不再是“只改一个 status”，而是完整的
认领业务：

```text
TODO → IN_PROGRESS
+ assigneeUserId
+ claim 记录
```

因此原 `updateInternshipTaskStatus` 只能保留 `IN_PROGRESS → DONE`（以及同状态
no-op）。前端“开始”按钮改走 `/claim`；不能同时保留一个只更新 status 的
`TODO → IN_PROGRESS` 捷径，否则会制造“进行中但无人认领、无认领记录”的任务。

## 9. 事务集成测试

单元测试不能证明数据库回滚。集成测试需要：

```text
准备 TODO 任务
→ 让 claim Mapper 更新成功
→ 让认领记录插入因唯一约束/故障失败
→ 结束事务
→ 新事务查询任务
→ status 仍是 TODO 且 assigneeUserId 仍为空
```

测试必须在验证阶段使用新事务查询，避免测试方法自己的回滚掩盖业务结果。
同时把新字段/新表补进 H2 `create_tables.sql`，并在 `clean.sql` 清理；否则
失败只是在说“测试数据库结构没同步”，还没有到事务逻辑。

## 10. 并发测试骨架

测试辅助 Bean 负责确保每个 worker 真正进入独立事务：

```java
@Service
public class InternshipTaskClaimTestFacade {

    @Resource
    private InternshipTaskService internshipTaskService;

    @Transactional(
            propagation = Propagation.REQUIRES_NEW,
            rollbackFor = Exception.class)
    public void claimInNewTransaction(Long taskId, Long userId) {
        internshipTaskService.claimInternshipTask(taskId, userId);
    }
}
```

它必须由 Spring 注入后调用；测试里 `new` 出来或同类 `this` 调用都不会经过事务
代理。

```java
int workers = 2;
Long tenantId = TenantContextHolder.getRequiredTenantId();
ExecutorService executor = Executors.newFixedThreadPool(workers);
CountDownLatch ready = new CountDownLatch(workers);
CountDownLatch start = new CountDownLatch(1);

List<Future<Boolean>> futures = LongStream.rangeClosed(1, workers)
        .mapToObj(userId -> executor.submit(() -> TenantUtils.execute(
                tenantId, () -> {
            ready.countDown();
            start.await();
            try {
                claimService.claimInNewTransaction(taskId, userId);
                return true;
            } catch (ServiceException ex) {
                return false;
            }
        })))
        .toList();

try {
    assertTrue(ready.await(5, TimeUnit.SECONDS));
    start.countDown();

    long successCount = 0;
    for (Future<Boolean> future : futures) {
        if (future.get(10, TimeUnit.SECONDS)) {
            successCount++;
        }
    }
    assertEquals(1, successCount);
} finally {
    executor.shutdownNow();
    assertTrue(executor.awaitTermination(5, TimeUnit.SECONDS));
}
```

`claimInNewTransaction` 必须确保每个 worker 使用独立事务；不能让测试外层同一事务把并发事实包住。
这里故意使用原生 `Executors` 制造真实并发，所以必须在父线程先捕获 `tenantId`，
再用 `TenantUtils.execute` 在每个 worker 中显式重建租户上下文。仅仅使用
`TransmittableThreadLocal` 并不等于任意原生线程池都会自动传播上下文；若漏掉
这一步，启用 `TenantDatabaseInterceptor` 的 MySQL 测试可能在真正竞争 SQL 前
就因租户为空失败。

最终查询：

```text
任务 status = IN_PROGRESS
assigneeUserId 非空
认领记录数量 = 1
认领记录 userId = 任务 assigneeUserId
```
