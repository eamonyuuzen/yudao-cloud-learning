## 4. Mapper 的条件状态更新

```java
default boolean startJob(Long id) {
    return update(new InternshipTaskJobDO(),
            new LambdaUpdateWrapper<InternshipTaskJobDO>()
                    .eq(InternshipTaskJobDO::getId, id)
                    .eq(InternshipTaskJobDO::getStatus,
                            InternshipTaskJobStatusEnum.PENDING.getStatus())
                    .set(InternshipTaskJobDO::getStatus,
                            InternshipTaskJobStatusEnum.RUNNING.getStatus())
                    .set(InternshipTaskJobDO::getStartTime, LocalDateTime.now())) == 1;
}

default void finishSuccess(Long id) {
    update(new InternshipTaskJobDO(),
            new LambdaUpdateWrapper<InternshipTaskJobDO>()
                    .eq(InternshipTaskJobDO::getId, id)
                    .eq(InternshipTaskJobDO::getStatus,
                            InternshipTaskJobStatusEnum.RUNNING.getStatus())
                    .set(InternshipTaskJobDO::getStatus,
                            InternshipTaskJobStatusEnum.SUCCESS.getStatus())
                    .set(InternshipTaskJobDO::getProgress, 100)
                    .set(InternshipTaskJobDO::getEndTime, LocalDateTime.now()));
}

default void finishFailed(Long id, String errorCode, String errorMessage) {
    update(new InternshipTaskJobDO(),
            new LambdaUpdateWrapper<InternshipTaskJobDO>()
                    .eq(InternshipTaskJobDO::getId, id)
                    .eq(InternshipTaskJobDO::getStatus,
                            InternshipTaskJobStatusEnum.RUNNING.getStatus())
                    .set(InternshipTaskJobDO::getStatus,
                            InternshipTaskJobStatusEnum.FAILED.getStatus())
                    .set(InternshipTaskJobDO::getErrorCode, errorCode)
                    .set(InternshipTaskJobDO::getErrorMessage,
                            StrUtil.maxLength(errorMessage, 512))
                    .set(InternshipTaskJobDO::getEndTime, LocalDateTime.now()));
}

default boolean rejectJob(Long id, String errorCode, String errorMessage) {
    return update(new InternshipTaskJobDO(),
            new LambdaUpdateWrapper<InternshipTaskJobDO>()
                    .eq(InternshipTaskJobDO::getId, id)
                    .eq(InternshipTaskJobDO::getStatus,
                            InternshipTaskJobStatusEnum.PENDING.getStatus())
                    .set(InternshipTaskJobDO::getStatus,
                            InternshipTaskJobStatusEnum.REJECTED.getStatus())
                    .set(InternshipTaskJobDO::getErrorCode, errorCode)
                    .set(InternshipTaskJobDO::getErrorMessage,
                            StrUtil.maxLength(errorMessage, 512))
                    .set(InternshipTaskJobDO::getEndTime,
                            LocalDateTime.now())) == 1;
}
```

条件更新阻止同一 job 被两个 worker 同时从 PENDING 取走。

## 5. 线程池

实验起始参数，不是生产默认：

```java
@Configuration(proxyBeanMethods = false)
public class InternshipTaskJobConfiguration {

    @Bean("internshipTaskJobTaskExecutor")
    public ThreadPoolTaskExecutor internshipTaskJobTaskExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(2);
        executor.setMaxPoolSize(4);
        executor.setQueueCapacity(20);
        executor.setKeepAliveSeconds(60);
        executor.setThreadNamePrefix("internship-job-");
        executor.setRejectedExecutionHandler(new ThreadPoolExecutor.AbortPolicy());
        executor.setWaitForTasksToCompleteOnShutdown(true);
        executor.setAwaitTerminationSeconds(30);
        executor.initialize();
        return executor;
    }
}
```

Yudao 的 `YudaoAsyncAutoConfiguration` 会为常见 TaskExecutor 设置 TTL TaskDecorator。集成时确认该自动配置在 system-server 中生效；不要同时假设和重复配置。

## 6. Service 提交

```java
@Service
public class InternshipTaskJobServiceImpl implements InternshipTaskJobService {

    @Resource
    private InternshipTaskJobMapper jobMapper;
    @Resource
    private InternshipTaskJobWorker jobWorker;

    @Override
    public Long createJob(String jobType, Long requesterUserId) {
        Long tenantId = TenantContextHolder.getRequiredTenantId();
        InternshipTaskJobDO job = new InternshipTaskJobDO();
        job.setJobType(jobType);
        job.setStatus(InternshipTaskJobStatusEnum.PENDING.getStatus());
        job.setProgress(0);
        job.setRequesterUserId(requesterUserId);
        job.setTenantId(tenantId);
        jobMapper.insert(job);

        try {
            jobWorker.execute(job.getId(), tenantId);
        } catch (TaskRejectedException ex) {
            jobMapper.rejectJob(
                    job.getId(), "QUEUE_FULL", "后台任务队列已满");
            // 第一版仍返回 jobId；调用者可查询到 REJECTED。
        }
        return job.getId();
    }
}
```

本方法第一版不要开启覆盖“insert + 提交线程池”的数据库事务。否则 worker 可能在外层事务提交前读取 job。需要更严格可靠性时改为事务提交后事件或 Outbox。

## 7. 独立 Executor Bean

```java
@Component
@Slf4j
public class InternshipTaskJobWorker {

    @Resource
    private InternshipTaskJobMapper jobMapper;

    @Async("internshipTaskJobTaskExecutor")
    public void execute(Long jobId, Long tenantId) {
        TenantUtils.execute(tenantId, () -> executeInTenant(jobId));
    }

    private void executeInTenant(Long jobId) {
        if (!jobMapper.startJob(jobId)) {
            return;
        }
        try {
            doBusinessWork(jobId);
            jobMapper.finishSuccess(jobId);
        } catch (Exception ex) {
            // 给调用者保存稳定、非敏感的摘要；完整堆栈只进服务端日志。
            jobMapper.finishFailed(
                    jobId, "JOB_EXECUTION_FAILED", "后台任务执行失败");
            log.error("[execute][jobId({}) 执行失败]", jobId, ex);
        }
    }

    private void doBusinessWork(Long jobId) {
        // 本阶段使用可控延迟/统计任务，不执行任意脚本。
    }
}
```

拆成另一个 Bean，确保 `@Async` 调用经过 Spring 代理。`tenantId` 是显式任务
参数；Worker 用 `TenantUtils.execute` 建立并在 `finally` 中恢复上下文，不把
一次 HTTP 线程快照当成可重启的长期事实。

恢复扫描的边界：

```java
List<InternshipTaskJobDO> jobs = TenantUtils.executeIgnore(
        () -> jobMapper.selectRecoverableJobs());
for (InternshipTaskJobDO job : jobs) {
    jobWorker.execute(job.getId(), job.getTenantId());
}
```

扫描必须定义“哪些 PENDING/超时 RUNNING 可恢复”，并用条件状态更新防止多实例
重复接管。上面只是恢复入口形状，不表示 Step 08 已实现可靠调度。

```java

InternshipTaskJobDO getJobForRequester(Long id, Long requesterUserId);

@Override
public InternshipTaskJobDO getJobForRequester(
        Long id, Long requesterUserId) {
    InternshipTaskJobDO job =
            jobMapper.selectByIdAndRequester(id, requesterUserId);
    if (job == null) {
        // 对“不存在”和“属于别人”使用同一错误，避免泄露 job 是否存在。
        throw exception(INTERNSHIP_TASK_JOB_NOT_EXISTS);

    return job;
}

default InternshipTaskJobDO selectByIdAndRequester(
        Long id, Long requesterUserId) {
    return selectOne(InternshipTaskJobDO::getId, id,
            InternshipTaskJobDO::getRequesterUserId, requesterUserId);
}
```

## 9. 关键测试

### 提交快速返回

```text
createJob
→ 返回 jobId
→ 当下允许仍是 PENDING/RUNNING
→ 不等待 SUCCESS
```

### worker 成功

```text
PENDING
→ execute
→ RUNNING
→ SUCCESS + progress=100 + endTime
```

### worker 失败

```text
人工抛异常
→ FAILED
→ errorCode/errorMessage 有值
→ HTTP 提交请求此前已经返回 jobId
```

### 双 worker

两个线程同时 `execute(jobId)`：

```text
startJob 条件更新只有一次返回 true
业务执行计数必须为 1
```

### 队列拒绝

使用很小线程池和阻塞任务填满：

```text
额外任务被 AbortPolicy 拒绝
job 变 REJECTED
API 返回 jobId，但查询状态明确为 REJECTED
```

## 11. 可靠性边界与恢复入口

当前实现：

```text
Job 行持久化
→ Runnable 只进入当前 JVM 内存队列
```

它不保证进程重启后继续执行。集成时至少留下恢复设计：

```text
应用启动/定时任务
→ 扫描超时 PENDING
→ 扫描超时 RUNNING
→ 按业务规则重投或标 FAILED
```

本阶段可只观察遗留状态，不必立即实现恢复；但不能把“数据库有行”写成“任务
已可靠入队”。Step 10 的 MQ 才会对比进程内队列与可恢复消息。

H2 测试资源必须同步新增 job 表并在 `clean.sql` 清理，否则现有
`BaseDbUnitTest` 还没运行到业务逻辑就会失败。
