# 第 11 步预览与第 12～15 步准入条件

> 本文件不是提前开课，而是防止两个月课程结束后再次临时设计路线。

## 1. 第 11 步只做三日预览

### 第 1 日：重新画微服务拓扑

```text
浏览器/Python Agent
→ Gateway
→ System Service
→ 另一个业务 Service
→ Nacos 注册发现
```

只回答：

- 每个服务是否独立进程；
- HTTP 第一个接收者是谁；
- Gateway 根据什么路由；
- Service 怎样注册与发现；
- 内部调用怎样传身份、租户和 traceId。

### 第 2 日：一条最小 Feign 调用

```text
业务服务
→ Feign 调 System 的用户摘要 API
→ 返回 userId + nickname
→ 拼接业务响应
```

重点不在注解数量，而在：

```text
API 契约属于谁
调用超时在哪里设置
业务错误怎样跨服务表达
Token/login-user/tenantId 怎样传递
对方服务关闭时当前服务怎样结束
```

### 第 3 日：四个故障实验

```text
服务名错误
目标服务关闭
Feign 超时
身份头丢失
```

记录“现象 → 边界 → 证据 → 根因 → 恢复”。

### 是否正式进入第 11 步

满足以下条件才继续完整学习：

- 第 7～10 步至少三个阶段有运行证据；
- 不再混淆网关和业务服务；
- 能在 IDE 外启动关键服务；
- Nacos 当前环境稳定；
- 当前目标确实需要跨服务，而不是为了“看起来微服务化”。

## 2. 第 12 步：高并发综合实战准入

不要因为学过 Redis 和线程池就自动开启。

准入条件：

```text
有稳定的并发测试/压测工具
→ 能记录 QPS、P95/P99、错误率
→ 数据库事务和原子更新已经跑通
→ 能观察连接池、线程池和 Redis
→ 先有一个会失败的朴素版本
```

推荐项目仍是限量资源领取，但第一版可以把“优惠券”换成更贴近当前业务的“限量实习名额”：

```text
活动名额 100
→ 1000 个并发领取
→ 防超发
→ 防同用户重复
→ 记录成功事实
```

不要在没有朴素版数据前同时加入：

```text
锁 + Lua + MQ + 缓存 + 限流 + 熔断
```

否则无法知道每个机制解决了哪个问题。

## 3. 第 13 步：性能、SQL、JVM 与可观测性准入

准入条件不是“知道 jstack 命令”，而是已经拥有可重复故障：

- 一个可稳定复现的慢 SQL；
- 一个可观察的线程池积压；
- 一个可控制的内存增长；
- 一条带 traceId 的跨层请求。

学习顺序：

```text
先观察业务症状
→ 指标判断资源
→ 日志/trace 定位请求
→ SQL/线程栈/堆进一步定位
→ 修复
→ 对照修复前后数据
```

暂不提前准备大量 JVM 源码或 GC 算法笔记；等真实症状出现时再选择代表性机制。

## 4. 第 14 步：可靠性与最终一致性准入

必须先真实遇见或模拟：

```text
数据库提交成功但消息发送失败
远程调用超时但不知道对方是否成功
重试造成重复副作用
一个异步 job 长期卡在 RUNNING
```

届时围绕同一业务逐步加入：

```text
状态机
超时扫描
有限重试
补偿
Outbox/本地消息表
人工介入
对账
```

不把 Seata/XA 当成第一课。先学清“未知结果”与业务恢复，再评估具体分布式事务方案。

## 5. 第 15 步：完整 Agent/MCP 作品准入

准入条件：

- 一个只读 Agent 已有固定评测和失败轨迹；
- 至少一个受控写能力具备确认、权限、幂等和审计；
- 异步 job 可查询和恢复；
- 工具 API 已被两个以上调用方复用，MCP 才有真实价值；
- RAG 有明确文档来源、权限与引用要求；
- 部署和可观测性不再完全依赖 IDE。

推荐最终作品：

```text
AI Knowledge Drive
→ Java 保存文档、权限和任务事实
→ 异步解析/分块/向量化
→ Python/Java Agent 调用受控工具
→ MCP 暴露稳定能力
→ 轨迹、评测、成本和审计
```

### MCP 的学习边界

先回答：

```text
工具原来如何本地注册
→ 通过 MCP 后谁是 Server、谁是 Client
→ capability/schema 怎样暴露
→ 身份、租户和权限怎样跨协议传
→ 多客户端复用解决了什么真实问题
```

不因为协议流行就把内部只有一个调用方的普通函数强行 MCP 化。

## 6. 两个月后如何决定路线

用证据选，不用焦虑选：

| 证据 | 建议 |
|---|---|
| 6B～10 都能复述但跨服务模糊 | 正式进入第 11 步 |
| 并发实验仍不稳定 | 回补第 7/9 步 |
| 工程闭环完整但缺作品表达 | 做综合作品、README、演示和求职材料 |
| Agent 工具稳定且确有多客户端 | 进入 MCP |
| 已有可重复性能瓶颈 | 进入第 12/13 步 |
| 出现跨服务未知结果 | 进入第 14 步 |
