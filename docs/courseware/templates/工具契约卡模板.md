# 工具契约卡模板

> 先决定业务边界，再让 AI 把它机械映射成 Pydantic、JSON Schema 或 Java DTO。

## 1. 一句话能力

```text
工具名：
它允许谁，在什么范围内，读取/改变什么：
明确不做什么：
```

## 2. 输入

| 字段 | 类型 | 必填/默认 | 范围 | 谁能决定 |
|---|---|---|---|---|
|  |  |  |  | 用户 / 运行时上下文 |

不要把 Token、tenantId、当前 userId 伪装成“让模型自由填写”的业务参数。

## 3. 返回与模型可见字段

| 字段 | 为什么模型需要 | 是否可能敏感 | 第一版是否返回 |
|---|---|---|---|
|  |  |  |  |

```text
注意：
RunContext 中的 Token 默认不发给模型
≠
工具返回也不发给模型
```

工具结果通常会进入下一轮模型消息，只返回完成回答所必需的字段。

## 4. 业务保护

```text
入口身份验证：
操作权限：
租户隔离：
行级数据范围：
业务状态/不变量：
最终事实拥有者：
```

若某一项当前尚未实现，写“未实现”，不要用“有权限的数据”模糊带过。

## 5. 失败语义

| 失败 | 对调用者的稳定语义 | 是否重试 | 谁产生 |
|---|---|---:|---|
| 参数非法 |  | 否 | Schema / 后端 |
| 未登录 |  | 否 | Agent 入口 / 后端 |
| 无权限 |  | 否 | 后端 |
| 暂时不可用 |  | 是 | 网络 / 下游 |
| 业务错误 |  | 通常否 | Service |

不要把后端堆栈、SQL、内部异常原文发给模型。

