# 使用与交接手册

## 1. 新的一天怎样开始

把下面这段发给 Codex 即可：

```text
主线：继续 Yudao 两个月课程。
先读取 docs/courseware/README.md、两个月执行总表.md 和当前阶段执行包。
先根据上次证据定位当前轮次，不重新设计路线。
按“人类逻辑 → 文件地图 → 我完成的关键判断 → 运行证据 → 收口”推进。
参考答案已经在 courseware/reference-code 和 learning-labs 中准备好，
解锁索引在 courseware/instructor/参考答案索引.md。
用户作答前不要读取索引或完整参考实现。
除非我完成尝试、连续受阻或明确要求，否则不要提前展开完整答案。
保留无关 Git 改动，不自动提交或推送。
```

## 2. Codex 每轮开始前要确认

```text
当前阶段和轮次
今天唯一根问题
本轮用户负责的关键判断
本轮允许 AI 自动完成的机械工作
一个第一入口 + 最多四个可选文件
正常与失败验收
明确不做的内容
```

如果缺少环境或上轮证据，可以先做只读检查；不要因为某个服务没启动就重写整套计划。

进入 Agent 第 5 日前先运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File learning-labs/internship-task-agent/scripts/preflight.ps1 `
  -RequireLive
```

它只报告配置是否存在，不打印 Token 或 API Key。

## 3. 三种代码材料

### 可运行 Lab

位置：

```text
learning-labs/
```

特点：

- 独立于 Yudao Maven 构建；
- 用于看清跨语言或框架循环；
- 有环境变量样例和自动测试；
- 不保存真实密钥和 Token。

### Reference Code

位置：

```text
docs/courseware/reference-code/
```

特点：

- 是未来 Yudao 代码的完整设计卡；
- 包含文件清单、完整关键方法、SQL 和测试形状；
- 只能通过导师索引按当前 Session 解锁；
- 开始该阶段时必须重新对照当前源码；
- 不能未经编译就宣称已经集成成功。

### 用户练习代码

位置：正常 Yudao 业务源码。

规则：

- 先保留用户正确实现；
- 当前轮只改确认的文件；
- 参考代码不是覆盖用户版本的命令；
- AI 接管前先说明差异和原因。

## 4. 每轮结束的最小交接包

```text
阶段/轮次：
今天的根问题：
已验证：
证据：
仍未验证：
停车场：
Git 状态：
下一轮第一动作：
24 小时冷启动题：
```

这样换电脑或换任务后，不需要依赖完整聊天记录。
阶段掌握使用 [阶段掌握评分量表](evaluations/阶段掌握评分量表.md)，不以“听起来
懂了”代替预测、诊断和迁移证据。

## 5. 跨电脑同步

稳定材料通过 Git 同步：

```text
课程文档
Lab 源码
测试
.env.example
不含密钥的启动脚本
```

每台电脑单独维护且不提交：

```text
.env
真实 Token
API Key
数据库密码
本地绝对路径
IDE 工作区缓存
模型缓存
```

换电脑后的恢复顺序：

```text
git pull
→ 查看当前阶段交接包
→ 复制 .env.example 为 .env
→ 填入本机配置
→ 启动依赖
→ 先跑自动测试
→ 再跑真实请求
```

## 6. 偏航恢复

出现以下信号时回到阶段总图：

- 连续出现五个以上新名词；
- 能解释单个函数但不知道请求现在在哪；
- 正在同时调试模型、权限、Redis 和线程池；
- 看了很多源码但没有一个运行现象；
- 不知道当前实验要证明什么。

恢复动作：

```text
停下新源码
→ 画出进程/模块边界
→ 只保留当前一次事件
→ 找到第一个异常现象
→ 选择一个证据源
→ 修复或解释后再扩大
```
