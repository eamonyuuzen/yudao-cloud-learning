# 大模型概念渐进融入路线

> 目标：为 Agent 工程建立足够的模型认知，但不把当前 Java 主线改造成模型训练课程。

## 1. 结论：学习到“轻中度机制层”

当前不建议完全跳过大模型知识，否则容易把模型、框架和工具调用都理解成不可解释的魔法。

也不建议现在单独投入一条重型理论线。更合适的是：

```text
第 6 步 Agent 主线照常推进
→ 每遇到一个真实工程问题，补一个对应的大模型概念
→ 用小实验观察行为
→ 回到 Agent 调用链
```

本阶段目标不是“会训练模型”，而是能够解释：

```text
模型为什么会选择工具
为什么工具参数可能错误
上下文为什么会丢失或变贵
为什么同一问题可能得到不同回答
本地模型为什么受显存、量化和上下文影响
怎样验证 Agent 不是碰巧成功
```

## 2. 三层深度

### A. 工程使用层：第 6 步必须达到

- 模型、模型提供方、SDK、Agent 框架不是同一个东西。
- Token、上下文窗口、消息角色和多轮历史。
- temperature 等生成参数为什么影响稳定性。
- 结构化输出与工具调用的区别。
- 模型只生成工具调用意图，框架和本地代码才真正执行工具。
- 幻觉、超时、限流、成本和延迟。
- 云端 API 与本地推理服务只是两种模型提供方式。
- 基本评测：固定输入、期望工具、期望参数、最终业务结果。

### B. 机制理解层：轻中度掌握

- 大模型的核心训练目标可以先理解为“根据已有 Token 预测下一个 Token”。
- Transformer、Embedding 和 Self-Attention 在整条链中的位置。
- 预训练、指令微调、对齐和推理的区别。
- 为什么工具描述和 JSON Schema 会影响模型选工具、填参数。
- 为什么长上下文不等于模型一定能正确使用全部信息。
- 参数量、量化、显存、上下文长度和推理速度的大致关系。

这一层只要求能用小例子解释因果，不要求推导完整公式。

### C. 训练与数学层：当前暂缓

- 从零训练或微调大模型。
- 完整反向传播、优化器和分布式训练。
- Attention 的完整矩阵推导。
- CUDA Kernel、推理引擎源码和算子优化。
- 系统性阅读模型论文和复现 benchmark。

以后如果工作明确涉及算法、模型训练或推理平台，再单开正式路线。

## 3. 学习方式

每张概念卡控制在 15～25 分钟：

```text
一句话人类本质
→ 它位于 Agent 链路的哪里
→ 一个极小例子或对照实验
→ 一个容易误解的边界
→ 回到当前项目
```

建议实验：

```text
temperature 低 / 高
→ 比较同一输入的稳定性

工具描述模糊 / 清楚
→ 比较工具选择与参数

上下文短 / 长
→ 比较延迟、成本和信息使用

云端模型 / 台式本地模型
→ 比较接口一致性、速度和能力

固定测试集重复运行
→ 观察非确定性与通过率
```

代码不是学习这些概念的唯一方法。可以使用：

- 人类逻辑图；
- 三个 Token 的手算注意力示意；
- 请求与响应对照；
- 模型行为实验；
- 错误案例复盘；
- 一页空白回忆图。

只有当代码能提供可观察证据时，才写最小实验。

## 4. 与第 6 步的对应关系

| 第 6 步场景 | 顺带学习的大模型概念 | 到什么程度 |
|---|---|---|
| 接云端模型 API | 模型、提供方、SDK、base URL | 能区分四者并切换配置 |
| 第一次工具调用 | Tool Calling、JSON Schema | 能解释模型不直接执行 Java |
| 工具参数错误 | Token、提示、描述、结构化输出 | 能提出一轮证据化改进 |
| 多轮对话 | 上下文窗口、消息历史 | 能判断状态由谁保存 |
| 两步工具调用 | Agent loop、确定步骤与模型步骤 | 能划分哪些步骤必须由代码控制 |
| 本地 Ollama | 推理、量化、显存、上下文 | 能解释机器为什么只能运行某类模型 |
| Agent 测试 | 幻觉、非确定性、评测集 | 能区分代码断言与概率性评测 |

## 5. 空窗期的轻复习

一周空窗期只插入两张卡，不增加每日总时间：

```text
Agent 复习日：
模型输出工具名和参数
→ 框架校验并执行
→ 结果再次返回模型

总图复习日：
模型 / 提供方 / SDK / Agent 框架 / Java Service
分别用一句话说明职责
```

## 6. 什么时候单开正式大模型路线

满足任一条件后再单开：

- 第 6 步完成后仍希望系统理解 Transformer；
- 实习或项目要求模型评测、微调、RAG 或本地推理；
- 已能稳定完成 Agent 工具闭环，但无法解释模型行为；
- 需要选择模型、上下文、量化或推理部署方案。

届时建议用 4～6 个独立学习簇展开：

```text
Token 与生成
→ Transformer 与 Attention
→ 训练、微调与推理
→ Embedding 与 RAG
→ Tool Calling 与结构化输出
→ 评测、成本与部署
```

在此之前，大模型知识是 Agent 主线的解释支架，而不是第二条重型主线。
